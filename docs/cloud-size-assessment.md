# 单份简历的云端存储大小

测量日期：2026 年 11 月 4 日。测量对象是当前 MyResume 的实际 `Resume`
结构，所有姓名、经历和联系方式均为新生成的虚构测试资料，没有读取用户的
浏览器 IndexedDB 或真实简历。

复现命令（项目根目录）：

```powershell
node --import tsx cloud/test-integration/measure-size.ts
```

## 正文与排版

云端保存可继续编辑的正文和排版 JSON。标题、语言、模块、条目、富文本、
配色、字体标识、布局、头像引用和版本号均包含在正文中。紧凑 JSON 的结果如下：

| 合成场景 | 经历/技能条目 | 中文详情字符约数 | 紧凑 JSON | 缩进 JSON |
| --- | ---: | ---: | ---: | ---: |
| 空白简历 | 0 | 0 | 3.18 KiB | 4.42 KiB |
| 常规简历 | 14 | 2,000 | 12.50 KiB | 18.31 KiB |
| 较长简历 | 36 | 6,000 | 29.34 KiB | 41.93 KiB |
| 内容丰富的简历 | 85 | 20,000 | 81.83 KiB | 109.41 KiB |

实际大小由字段数、文本长度、富文本结构和自定义模块决定。这些是用于容量
规划的具体合成样本，不是所有用户简历的统计平均值。常规文字简历可先按
约 **10–35 KiB 正文**估算；包含很多经历或长段落时可能达到 80–100 KiB 或更大。

## 头像

头像是独立的图片数据，通常比正文大。以常规样本的 12,795 字节正文为例：

| 头像二进制大小 | 正文加头像的逻辑存储大小 |
| --- | ---: |
| 没有头像 | 12.50 KiB |
| 200 KiB | 212.50 KiB |
| 1 MiB | 1.012 MiB |

云端正文和图片分开存储；图片以二进制分块保存。API 传输时使用 Base64，
这会使图片的传输字符串约增加三分之一，但不应把这部分传输膨胀计作二进制
云端存储大小。SQLite/D1 的索引、页、用户与会话元数据仍会占用额外空间，
管理员看到的逻辑字节数不等于整个数据库文件的物理大小。

全站共享字体、PDF 渲染库和模板资源不随每份简历重复保存。导出的 PDF、PNG
或原始导入文档也不属于保存可编辑简历所需的数据。

## 数量配额与字节上限

每位用户默认可保存 10 份云端简历，管理员可以调整。这个数量统计的是
逻辑简历；头像和本地历史不会被算成额外的“份数”。

当前方案每份正文上限为 512 KiB，引用的头像上限为 5 MiB，上传请求总上限
为 8 MiB。大于上限时应明确提示用户缩小内容或图片，本地编辑数据仍保留。

第一版云端保存当前版本；现有最多 50 份完整历史快照继续留在本机。常规样本
的 50 份正文历史约占 618 KiB，若以后将历史也存到云端，必须另行计入容量，
并继续复用同一张头像数据。
