# 第四阶段：输出与网络验收

2026-11-07 完成本地发布候选，并于同日推送、发布和完成线上验收，见 [发布记录](releases/2026-11-07-instant-preview.md)。本文保留发布前本地测量：优化前网络基线取自 2026-11-06 的 `429ec1c` 构建；使用同一 Windows 环境、Chrome 156.0.8078.80、1440×980 视口。总计划见 [产品优化计划](product-polish-plan.md)，原始本地指标见 [量化记录](measurements/output-stage4-2026-11-07.json)。

## 改动与依据

1. 首页、文件备份页和导出面板不再静态引入导入窗口及解析器；历史记录也在点击后加载。加载期间可取消，网络失败可重试，关闭后迟到的加载结果不会重新打开窗口。
2. 每次只读取所选家族的字体目录。构建从总目录生成六个独立目录，保留路径、SHA256、长度和字符覆盖校验。总目录仍作为离线生成与验证来源。
3. 根据 DOM 实际字重与字体样式分组文字。正文字符不再同时下载没有使用它们的粗体或斜体字形；后续加粗或斜体时补齐对应分片。
4. 带哈希的 JS、CSS、模板图片使用长期缓存；HTML、未带哈希的字体目录继续重新验证，账号接口继续 `no-store`。
5. 修复长列表 PDF 中编号单独留在上一页的问题：编号与首段共用文字排版与孤行保护，长条目仍可跨页。递增渲染版本使旧 PDF 缓存失效。导出面板改为明确说明使用“精确 PDF”的字体和分页。

联网参考并核对了 [React 的按需加载](https://react.dev/reference/react/lazy)、[web.dev 字体性能建议](https://web.dev/articles/font-best-practices)、[Cloudflare 静态响应头](https://developers.cloudflare.com/workers/static-assets/headers/)和[平台限制](https://developers.cloudflare.com/workers/platform/limits/)。实际延迟加载采用有取消和失败重试状态的对话框包装；未改动本机／云端数据契约。

## 冷热缓存与慢网

同一默认虚构简历、2 页、无照片。每种条件各 3 次导航，取中位数；样本数量不足以报告 p95。冷缓存通过 Chrome DevTools Protocol 清空 HTTP 缓存；热缓存紧随对应冷缓存运行。限制为下行 200,000 字节／秒（1.6 Mbps）、上行 93,750 字节／秒、150ms 延迟，不限 CPU。

| 条件 | 首个预览：前 → 后 | 字体稳定：前 → 后 |
| --- | ---: | ---: |
| 本地不限速，冷缓存 | 248.5 → 248.6ms | 460.0 → 378.6ms |
| 本地不限速，热缓存 | 222.8 → 207.3ms | 376.5 → 327.8ms |
| 模拟慢网，冷缓存 | 3265.3 → 3101.3ms | 12879.2 → 10450.1ms |
| 模拟慢网，热缓存 | 719.1 → 720.9ms | 1194.4 → 1174.3ms |

冷缓存子资源传输量从 2,347,910 降至 1,869,846 字节，减少约 20.4%。普通示例的字体文件从 6 个、1,529,516 字节变成 5 个、1,350,340 字节。所需家族目录为 107,874 字节，gzip 为 38,433 字节；旧总目录的 gzip 为 303,925 字节。Vite 本地响应已有 gzip 压缩，因此不能把本地测量称为“未压缩下载”；也不能当作真实 Cloudflare 的网络、压缩协商或缓存性能。

首次内容仍先用回退字体显示，字体到齐后重排。慢网首次稳定字体仍需约 10.45 秒，是剩余优化点；此次没有把它表述成瞬时加载。热缓存首屏变化接近测量波动，不宣称提速。

一次未固定前台状态的实验混入约秒级动画帧节流，未用于前后结论。最终脚本启用焦点模拟，逐轮记录页面可见性和长帧间隔；正常视口均为 visible。冷导航最多约 438ms 的长间隔包含限速导航与初始化，不是单次编辑耗时。基线与结果跨两天记录，网络模拟相同，但不是跨设备实验。

## 编辑与模板切换

生产构建通过原生 input／click 事件进入 React store，等待分页内容和下一动画帧；包含 store、HTML 生成、按需字体判断及分页。字体已缓存，各 20 次，p95 使用最近秩。第二阶段只计运行时更新，不能直接与下表比较。

| 样本 | 编辑中位数 / p95 | 切换模板中位数 / p95 |
| --- | ---: | ---: |
| 2 页 | 38.9 / 50.5ms | 33.4 / 35.7ms |
| 10 页长侧栏 | 66.7 / 77.1ms | 59.1 / 71.4ms |

普通样本在清简／条理间切换，始终 2 页；长侧栏在并列／色带间切换，始终 10 页。这两对模板复用同一已加载字体，跨字体的首次切换另受下载影响。全部测量保持同一个 iframe 文档。

## 输出与资源验收

- 16 模板、6 字体及 5 个长内容／列表代码／双栏／照片压力样本：27 组 PDF／HTML、73 页 PDF、191 次模块字符计数比对全部通过。检查字体嵌入、常规／粗体／斜体区别、链接注释、照片、隐藏内容未导出、页面边界、长文结尾和重复段落完整性。
- 首轮发现第 19 个列表编号单独留在第 1 页；修复后孤立编号数为 0。六张联系表和代表页视觉复查通过。字符计数不是逐像素或所有换行完全相同的证明。
- 通过真实 UI 下载 JSON、PDF、HTML、双页图片 ZIP、单页 300 DPI PNG。双页 ZIP 含两张 1241×1754 PNG；300 DPI 图为 2481×3508。离线 HTML 有正文与照片，无脚本或外部资源请求，使用系统字体回退。
- 本地 Wrangler 加载准备发布的资源，6 条响应头规则生效。再次导航时 9 个带哈希资源直接来自浏览器缓存（transferSize 为 0）；家族目录重新验证，匿名账号接口重新获取。未写入生产账户。
- 资源包 1020 个文件，共 718,344,432 字节；最大单文件 15,378,948 字节（约 14.67 MiB），低于核对过的 25 MiB 单文件限制。这个总量包含全部字体及交付格式，不是单次浏览器下载量。696 个字形分片的长度与 SHA256 全部匹配，六个家族目录与源目录一致。
- 208 个自动测试通过，类型检查与生产构建通过；按需窗口的正常、取消、失败重试流程通过。16 模板、375px、手动精确 PDF 和实际 PDF 下载在本地 Wrangler 回归通过，即时模式的 PDF 专用资源请求为 0。

## 复现与边界

`pnpm build` 生成前端及家族字体目录；`node scripts/prepare-cloud-assets.mjs` 准备 Cloudflare 资源。`pnpm exec tsx scripts/verify-stage4-exports.ts` 和 `python scripts/verify-stage4-exports.py` 生成与核验输出矩阵；Python 需要 pdfplumber、pypdf、Pillow 和 Poppler。矩阵脚本同时生成长侧栏的 JSON 测试备份。

浏览器脚本见 `tests/browser/*stage4.js`：network、interaction、exports、deferred-dialogs、deferred-dialog-failure、cache。`scripts/verify-stage4-delivery.mjs` 只访问本地 Wrangler，并验证缓存头、资源大小及字体哈希。原始文件保存在忽略目录 `output/stage4/`，量化 JSON 入库。

这是发布前本地验收记录。发布后的真实网络冷／热缓存与功能检查另见 [线上发布记录](releases/2026-11-07-instant-preview.md)，不与本文模拟网络数据混用。当前启动仍等待账号识别，本轮未改变账户隔离策略。HTML 与 PDF 采用不同引擎，最终投递版继续用精确 PDF 核对。构建的已有 fflate／HTML 动静态导入重叠警告保留。
