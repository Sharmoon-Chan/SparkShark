# 第二阶段：即时 A4 分页与渐进字体

2026-11-06。本地实施和核验完成，已分批提交，尚未发布。阶段计划见 [产品优化计划](product-polish-plan.md)，完整原始指标见 [阶段 2 量化记录](measurements/preview-stage2-2026-11-06.json)。

## 实现

预览 iframe 只初始化一次。后续编辑替换受控的内容和样式，保留文档、FontFaceSet 和已加载字形。内容、头像及字体变化合并到动画帧重测；只观察隐藏测量区，输出页不会反过来触发观察循环。自动保存的 revision／updatedAt 变化不会重复分页，缩放只改变显示比例。

分页器测量真实文字行矩形，按 A4 宽度、高度生成页面。逻辑分组和左右栏分配保留，双栏独立流动。短条目、标题及其后两行尽量同页，长段落、列表和代码按实际行断开。页码预留与现有 PDF 的底部空间计算对齐。字形超出行框的上沿也被纳入范围，避免中文大标题顶部被裁切；无法安全拆分的块给出错误，不静默丢内容。

视觉分页采用裁剪片段并剔除整块不可见内容。视觉克隆从无障碍树和 Tab 顺序排除，另保留一份完整的语义阅读副本及模块编辑按钮；键盘进入该副本时，高亮并滚动到相应可见模块。滚动位置按分组、栏、模块及源内容偏移恢复，避免字体到达或编辑时跳回顶部。

## 字体交付

根据现有原生 TTF 生成 6 家族、24 样式的 WOFF2 分片。基本字符、常用汉字和其余字符分组；其余每组至多 1024 个码点。所有样式、字形覆盖和许可保留，未替换 PDF 所用 TTF。

初屏先显示回退字体。浏览器只读取当前内容需要的字形组，斜体仅在可见内容用到时加载。父页面校验同源资源路径、大小与 SHA256，将 ArrayBuffer 交给 iframe 的 FontFace；iframe 仍禁止脚本和用户提供的外部资源。字体请求可取消、失败可重试，普通输入复用已加载字形。生成的联系方式图标使用系统字体，不被误报为用户内容缺字。

全部 696 个文件合计 152,167,540 字节（约 145.12 MiB），最大文件 1,072,136 字节；这是部署资源总量，不是每次下载量。24 样式的分片哈希、并集覆盖和与原始字库的一致性验证通过。

同一普通示例实际所需的常规两字重：

| 家族 | 字形分片总字节 | 约 MiB |
| --- | ---: | ---: |
| 黑体 | 1,529,516 | 1.46 |
| 宋体 | 2,039,888 | 1.95 |
| 文楷 | 2,873,120 | 2.74 |
| Plex | 1,694,904 | 1.62 |
| 圆体 | 2,281,972 | 2.18 |
| 思源黑体 | 1,529,232 | 1.46 |

文字范围或斜体增加会请求更多分片。分片路径带哈希并长期缓存，目录每次会话重新验证，不把本机吞吐等同于公网体验。

## 测量与验收

在 Windows Chrome 156、Vite 开发模块、前台可见 iframe 中，以字体已加载的两个合成样本各执行 20 次程序化编辑。计时包含 HTML 生成、更新、分页及下一帧，不含人工输入、React store 流转或公网字体下载。中位数为中间两项均值，p95 为最近秩。

| 样本 | 页数 | 更新中位数 | 更新 p95 | 纯布局中位数 | 纯布局 p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 普通逻辑双页 | 2 | 16.75ms | 22.30ms | 1.90ms | 2.30ms |
| 长侧栏双栏 | 10 | 55.50ms | 66.70ms | 6.75ms | 9.50ms |

早期隐藏／后台 iframe 的测试遭遇约 1 秒动画帧节流，已排除，不能用其结果评价正常前台编辑速度。样本与排序后的全部计时数据保存于量化 JSON。这仍不是跨设备或线上性能承诺。

功能检查：

- 9 类样本涵盖空白、双逻辑页、6 页长段落、6 页列表代码、10 页左右长侧栏、自定义字段、5 页超长页眉和照片、关闭页码。源行与显示行计数一致，实际输出的可见文字矩形截行数均为 0。
- 这 9 类样本与六款字体的普通示例，共 15 个 HTML/PDF 页数对照均相同。尚未宣称两个引擎的所有换行或坐标完全一致，精确 PDF 校对入口保留。
- 字体网络被阻断时仍可编辑，恢复后重试成功。A→B→A 取消、共享请求、损坏资源、过期响应与缓存边界有单元测试。
- 编辑期间 iframe 文档保持同一对象；10 页样本滚动位置 2500px→2500px，缩放不触发重新分页；即时模式不请求 PDF Worker／完整 TTF。
- 生产构建中，16 模板、20:16:14 字号层级、375px 窄屏、手动精确 PDF 和实际下载通过。
- 32 个测试文件、203 项测试通过，`pnpm build:cloud` 成功。

## 复核

生成：`scripts/prepare-browser-fonts.py`，可指定 `--family` 和 `--workers`。使用 Python 3.10+ 及 fontTools/Brotli；正常构建使用已生成资源。`scripts/verify-browser-fonts.py` 不重建资源，只校验全部分片及覆盖。

浏览器脚本：`tests/browser/pagination-stage2.js`、`pagination-stage2-integration.js` 在隔离的 Vite 开发会话中运行；PDF 对照由 `pnpm exec tsx scripts/verify-dom-pagination.ts` 生成。普通生产构建流程用 `tests/browser/preview-performance.js` 验证。

本次也修复了原交付生成脚本的 `preview_bytes` 未定义问题，保持原脚本可复现。旧阶段记录按当时实现保留，本文件描述当前状态。
