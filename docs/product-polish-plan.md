# 产品优化计划与阶段验收

2026-11-06。目标是让编辑、预览、模板与导出形成一致的使用体验。保留当前本地原型和已有业务能力，按阶段落实并记录测量。本轮先完成阶段 1；后续按本计划继续。

## 基线

- 当前正式站为 `b5cd09e` 对应的预览性能版本，发布记录见 `releases/2026-11-05-preview-performance.md`。
- 本地已增加即时 HTML 预览、16 张固定示意图、正文 400／粗体 700 和 20:16:14 默认字号层级，尚未提交或发布，见 `instant-preview-prototype.md`。
- 当前主要体验问题：预览区三层横条、模板目录说明重复且卡片过大、界面大量浅绿导致层级偏弱、即时预览与精确 PDF 的字体分页不同。
- 使用相同虚构示例，固定 1440×980 桌面与 375×812 移动视口保存阶段前后截图；更宽桌面与平板补测。

## 阶段 1 的边界与判断

这一阶段不改变正文排版、模板默认值、数据格式或云端保存逻辑。界面色彩整理只作用于工作台控件，不改变简历纸张的主题色。即时／精确两个入口保留；合并为一条预览头栏，差异说明移入可访问的帮助对话框，并保留简短连续排版提示，避免把即时模式误认为最终 PDF。

模板保留筛选、当前选中状态、固定示意图和键盘选择，移除重复的状态行及开发术语。更大视口增加列数，窄屏至少两列。完整度不再长驻三行，详细缺项仍可通过“检查简历”查看，保存异常与云端冲突保持醒目。

## 实施约定

1. 每个阶段先记录具体范围、参考来源和验收指标，再编辑代码。
2. 优先查官方资料或可核对的公开实现；区分已验证的行为和计划采用的方案。TalenCat 的公开资源参考与本地适配区别已记入 `instant-preview-prototype.md`。
3. 保留既有用户编辑及本地原型；使用隔离测试会话和虚构简历，不操作用户正在编辑的简历内容。
4. 阶段验收使用针对性功能检查、生产构建与视觉复查；不把单次本机耗时当作公网性能结论。
5. 阶段记录附修改前后截图、测量条件、通过项目和剩余边界。后续提交继续按功能拆分，本地评审完成后再发布。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 纸张顶部距浏览器内容区顶部 | 229px | 136px |
| 模板列表顶部 | 386.7px | 217.2px |
| 模板列数 | 2 | 3 |
| 完整度条高度 | 91.8px | 46px |

1920px 模板为 5 列，1024px 为 5 列，768px 为 4 列，375px 为 2 列。即时／精确模式均检查窄屏无文档横向溢出；页面内部仍允许用户主动放大预览后水平滚动。

通过检查：16 个模板及 8/8 筛选；键盘应用模板；帮助对话框的 Enter／Escape 和焦点返回；检查简历与本机保存；精确 PDF 加载与拖动布局入口。即时模式拦截 PDF 专用脚本和完整字体资源时仍正常工作，实际请求数量为 0。`pnpm build` 与类型检查通过。纯工作台样式调整没有新增镜像单元测试，浏览器回归脚本为 `tests/browser/workbench-stage1.js`。

原始截图保存在忽略目录 `output/playwright/polish-stage1-before.png`、`polish-stage1-after.png`、`polish-stage1-mobile-preview.png`、`polish-stage1-mobile-templates.png`。结构化记录见 [阶段 1 量化记录](measurements/workbench-stage1-2026-11-06.json)。这些是界面几何测量，不是性能加速数据。云端冲突逻辑和提示入口保持原实现，本次没有制造真实云端冲突或写入远程账户。

### 阶段 2：本地完成

已完成稳定预览文档、DOM A4 分页、按文字范围加载 WOFF2、失败重试、滚动锚点与语义阅读副本。9 类样本实际可见文字截行数为 0；共 15 个 HTML/PDF 页数对照相同。双页与 10 页样本各 20 次程序化更新的中位数为 16.75ms／55.50ms，p95 为 22.30ms／66.70ms。完整环境、范围和剩余差异见 [第二阶段记录](preview-stage2.md)。以下设计依据保留用于后续对照。

按 2A DOM 分页 → 2B 渐进字体 → 2C 输出对照依次验收：

- **2A** 保持固定宽度的测量 DOM，按模块／条目边界分页；超长段落再按实际行矩形拆分。先解决 iframe 每次 `srcDoc` 更新造成的文档重建，保留滚动位置与编辑定位。
- **2B** 第一屏仍使用可用字体；仅选中字体异步到达后重测，不以字体 ready 阻塞文字显示。当前 CSP 的 `font-src 'none'` 需要调整为受控同源资源，而非放宽全部权限。
- **2C** 统一边距、字号、行高等变量，逐项记录 HTML 与 PDF 的页数和换行差异。浏览器与 react-pdf 是不同引擎，相同字体不能自动保证分页相同；在差异可控前保留精确校对。

后续测量固定设备与浏览器，区分冷／热缓存，以 2 页和 10 页样本进行至少 20 次编辑，记录中位数与 p95；旧的单次 151／180ms 不作为 p95 结论。

本次只读联网调研的主要来源：

- [TalenCat 公开 Preview 模块](https://assets.talencat.cn/web/assets/Preview-YgWaN82q.js)：DOM 尺寸、ResizeObserver、rAF 与字体 ready 后重测，分页显示与导出职责分离。
- [CSS Font Loading 标准](https://www.w3.org/TR/css-font-loading-3/#font-face-set-ready)：字体及相关布局完成通知。
- [CSS Fragmentation 标准](https://www.w3.org/TR/css-break-3/)：断页、标题与正文及孤行控制语义。
- [Paged.js 官方架构](https://pagedjs.org/en/documentation/4-how-paged.js-works/)：分页改造 DOM 的方式，仅作为候选设计参考，未经编辑性能基准不直接引入。
- [ResizeObserver 文档](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver)：尺寸写入引发观察循环的风险，测量／写入应分离并跳过相同结果。
